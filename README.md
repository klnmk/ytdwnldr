# СЪЁМ — portable YouTube downloader

Небольшая Windows-утилита на Python / Qt. Интерфейс полностью на русском: ссылки, превью, выбор видео из плейлиста, настройки формата и очередь в одном окне. Оригинальная графика, Oswald / Golos Text и палитра бумаги, чёрной краски, лайма и голубого вдохновлены независимыми музыкальными афишами.

## Запуск готовой сборки

Откройте `dist/ytdwnldr-portable/ytdwnldr.exe`. Для переноса скопируйте **всю** папку `ytdwnldr-portable`, включая `_internal`, `bin` и `data`. Требуется Windows 10/11 x64. Python, FFmpeg, PATH, установка и права администратора для использования не нужны.

Готовый архив — `dist/ytdwnldr-portable.zip`; распакуйте его полностью в папку с правом записи. SHA-256 находится в соседнем `.zip.sha256`. Окно подстраивается под экран; на небольшой высоте доступна вертикальная прокрутка.

1. Вставьте ссылку YouTube. Данные загрузятся автоматически; кнопка «Добавить» и Enter выполняют ту же операцию.
2. Для плейлиста отметьте нужные записи. Несколько ссылок можно вставить через пробел или с новой строки; переключатель материалов появится над превью.
3. Выберите «Видео» / «Аудио», формат и качество. Нажмите «Скачать».
4. Следите за очередью; справа у каждой задачи есть «Отменить», «Повторить» или «Папка». Правый клик открывает дополнительные действия; Enter выполняет действие выбранной строки.

Сочетания: `Ctrl+L` — поле ссылки, `Ctrl+Shift+V` — вставить из буфера, `Ctrl+Enter` — скачать выбранное, `Ctrl+,` — настройки.

## Что реализовано

- Видео / Shorts / записи завершённых эфиров и плейлисты; асинхронное извлечение метаданных, название, канал, длительность, миниатюра.
- MP4: 360 / 480 / 720 / 1080 / 1440 / 2160p и лучшее доступное. Для одиночного видео показываются фактически найденные разрешения. Выбранное недоступное качество отключает скачивание; в плейлистах проверяется каждая запись, ошибка не останавливает остальные.
- Быстрый режим сохраняет исходные кодеки, объединяя и перепаковывая потоки в MP4. Режим совместимости выдаёт H.264 / AAC, перекодируя только несовместимые потоки; размер и частота кадров сохраняются. В интерфейсе указано, когда возможна конвертация.
- MP3: libmp3lame, 128 / 192 / 256 / 320 кбит/с; исходный M4A / AAC без перекодирования; WAV / PCM 16 бит. Название и автор записываются в теги, обложка добавляется по возможности. Ошибка обложки сохраняет готовый медиафайл.
- Если прямой публичный поток отклоняет запрос, используется доступный HLS-поток с тем же разрешением видео / исходным звуком. Недоступные и закрытые материалы остаются ошибкой; выбранное видео не заменяется меньшим разрешением.
- Плейлисты: выбрать / снять всё, недоступные записи, числовые префиксы исходного порядка, отдельная папка, независимые ошибки и повтор только неудачных задач. Список на Qt model/view без отдельных виджетов на каждую запись.
- Очередь: 1–4 параллельных загрузки (по умолчанию 2), состояния метаданных, загрузки, объединения и конвертации, процент, скорость, оставшееся время, отмена, повтор, защита от дублирования активных задач и история последних 300 завершённых задач. Активные задачи сохраняются независимо от этого ограничения.
- При отмене / закрытии Windows Job Object уничтожает процесс задачи и все дочерние Deno / FFmpeg. Задачи после перезапуска отмечаются прерванными; «Повторить» использует оставшиеся части, если yt-dlp / источник допускают продолжение.
- Unicode / кириллица, безопасные имена Windows, защита от перезаписи и коллизий одновременных задач. Ранее скачанное пропускается только при совпадении служебной квитанции; чужой одноимённый файл получает альтернативное имя новой загрузки.
- Настройки папки, формата, качества, MP3, параллельности, подкаталогов плейлистов, имён и существующих файлов. Светлая тема; тёмная тема не реализована.
- Нет браузера, веб-сервера, рекламы, телеметрии, автоматических обновлений или фоновых сетевых запросов при запуске.

## Portable-данные

`data/settings.json`, `data/history.json`, `data/logs/`, `data/cache/`, `data/jobs/` создаются рядом с EXE. Папка по умолчанию — `downloads` рядом с приложением. Внутренние пути сохраняются относительно portable-папки и переезжают вместе с ней; специально выбранная внешняя папка сохраняется абсолютным путём.

Если папка приложения защищена от записи, отображается сообщение о необходимости перенести всю папку. Данные не перенаправляются в AppData и не записываются в реестр. В папке назначения `.syom/` хранит квитанции, блокировки имён и незавершённые части. Их можно удалить при отсутствии работающих загрузок, если продолжение не нужно. Удаление квитанций отключает распознавание ранее скачанных файлов, но не снимает защиту от перезаписи.

Миниатюры кешируются на диске только при запросе материала, миниатюры каждой записи большого плейлиста не загружаются. Журнал GUI ограничен 3 × 1 МБ с ротацией; технический журнал рабочих процессов — `workers.log`. При необходимости его можно удалить после закрытия приложения.

## Разработка и сборка

Нужен Windows x64 Python 3.12 или новее. Проверенная среда разработки — Python 3.12. Интернет нужен для первой сборки и загрузок, но не для открытия готового приложения.

```powershell
build.bat
```

Скрипт создаёт локальную `.venv`, устанавливает точные версии из `requirements.lock.txt`, проверяет и распаковывает FFmpeg / ffprobe / Deno и шрифты по SHA-256 из `tools.lock.json`, запускает тесты, выполняет PyInstaller `onedir` и собирает `dist/ytdwnldr-portable/`. Повторные сборки используют `.tools-cache`. Публичные источники файлов и их контрольные суммы перечислены в lock-файле.

```powershell
.venv\Scripts\python.exe main.py
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts\verify_gui.py
```

`run.bat` запускает исходники через локальный Python без консольного окна. `scripts/verify_gui.py` создаёт изображения реальных Qt-виджетов с **синтетическими** данными для проверки дизайна в `artifacts/`; эти данные и изображения не входят в рабочее приложение. `ytdwnldr.exe --verify-startup` выполняет автономную проверку запуска: сохраняет пустое окно в `data/startup-verification.png` и завершается через 8 секунд.

`scripts/verify_release.py` проверяет перенос EXE и запуск с изолированным PATH; сетевые сценарии находятся в `verify_downloads.py`, `verify_selected_playlist.py` и `verify_live_queue.py`. После сборки и обновления `VALIDATION.md` команда `.venv\Scripts\python.exe scripts\finalize_release.py` синхронизирует документацию / `source.zip`, создаёт portable ZIP, проверяет CRC и записывает SHA-256. Этот шаг не пересобирает EXE: при изменениях приложения сначала выполните `build.bat`.

Обновление источников / digest — отдельная операция сопровождения: отредактировать версии и URLs, затем `python scripts/fetch_tools.py --refresh-lock`, проверить издательские суммы и diff. Обычная сборка не меняет lock-файлы. yt-dlp меняется вслед за YouTube; обновляйте его и `yt-dlp-ejs` согласованно, повторяя интеграционные проверки.

## Устройство проекта

| Файл | Ответственность |
|---|---|
| `app/domain.py` | состояния, валидация URL, настройки и имена |
| `app/storage.py` | portable-пути, атомарная запись настроек и истории |
| `app/engine.py` | yt-dlp, выбор потоков, FFmpeg, квитанции и блокировки |
| `app/worker.py` | отдельный процесс, JSON-протокол и диагностика |
| `app/process.py` | QProcess и Windows Job Objects |
| `app/queue.py` | параллельность, отмена, повтор, история |
| `app/ui/` | русские Qt-виджеты, модели списков, настройки и стили |
| `assets/` | оригинальные SVG, открытые шрифты и перевод Qt |
| `scripts/`, `tests/` | сборка, визуальная проверка и тесты |

## Проверка и ограничения

Автотесты покрывают валидацию URL / плейлистов, выбор точного разрешения, параметры yt-dlp, имена и номера, сохранение и перенос настроек, коллизии, существующие файлы, очереди, отмену / повтор, отсутствие ложного завершения и большой список. Интеграционные тесты создают собственный односекундный тестовый сигнал, проверяют настоящие MP3 / MP4 / WAV через ffprobe и уничтожение дерева процессов Windows. Сетевые сервисы замоканы только в тесте полной локальной цепочки; полученные файлы не являются доказательством загрузки с YouTube.

Фактические результаты сборки, тестов, запуска EXE и измерений записаны в `VALIDATION.md`.

Для ручной проверки с материалом, на который есть разрешение:

1. Видео с 1080p: проверить метаданные, доступность 1080p, загрузить MP4, воспроизвести изображение и звук. Проверить оба режима и сохранение fps / размера через ffprobe.
2. То же видео: MP3 320, проверить теги, обложку и папку. Проверить M4A при наличии AAC и WAV.
3. Плейлист: снять / выбрать всё, оставить несколько записей, MP3 192. Проверить папку и префиксы исходных номеров, независимые ошибки и повтор.
4. Во время скачивания / конвертации: менять размер окна, отменять задачи, закрывать приложение, убедиться в отсутствии оставшихся процессов. Повторить прерванную задачу.
5. Переместить **всю** папку на отдельный Windows 10/11 x64 компьютер без Python / FFmpeg; запустить без интернета, затем проверить загрузку и сохранение настроек. Проверить 100 / 125 / 150% DPI.
6. Проверить неверную ссылку, недоступное / приватное видео, отсутствие выбранного качества, отключённую сеть, запрет записи и отсутствие инструментов в bin. В UI должны быть русские сообщения, в журналах — детали.

Завершённые записи эфиров поддерживаются, активные прямые эфиры отклоняются. Авторизация через cookies / аккаунт, DRM, закрытые и защищённые материалы не поддерживаются. YouTube может ограничивать публичное извлечение для отдельных IP, регионов или роликов. Такое ограничение отображается как ошибка, а не обходится. M4A без исходного AAC недоступен. Прогресс FFmpeg рассчитывается по времени, если длительность известна; при неизвестной длительности показывается состояние обработки. Скорость и процент при загрузке относятся к текущему потоку; при переходе со звука на видео счётчик может начаться заново.

EXE не подписан. Переносимость на отдельном физическом компьютере и ручное воспроизведение в разных медиаплеерах требуют ручной проверки из списка выше. Лицензии и требования к дальнейшему публичному распространению перечислены в `THIRD_PARTY.md`; portable-папка содержит исходники приложения `source.zip`.
